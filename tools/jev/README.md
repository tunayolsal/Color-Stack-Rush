# Direct Jev AI play tests

This runner uses TypeSafe **`jev-1.13.0`**, not a browser automation agent or Jev Ultrafast. Jev receives a JSON description of the current camera-visible scene and HUD, then chooses one of five bounded drags. The game keeps running while the request is in flight. This tests decisions from observed geometry; it does not test Jev's image understanding or establish human difficulty.

The key stays in the Python process. No SDK dependency is required: the driver calls the documented HTTP Choice endpoint directly over a persistent HTTPS connection, with exactly one attempt per frame. One API request is in flight at a time, requests are spaced at least 250 ms, stale answers older than 500 ms are rejected, and each run is limited to 256 calls (8,192 for the worker). A broken connection is closed; only a later fresh observation may reconnect, never the same request.

1. Run `python tools/jev/test_driver.py` for the credential-free worker unit tests.
2. Start `python tools/jev/driver.py --output <absolute-test-artifact-directory>`. Set `TYPESAFE_API_KEY` in this process's environment, or pass `--env-file <existing-ignored-env-file>`. The worker binds only to `127.0.0.1:8877`. Do not reuse another agent's server.
3. Prefer the watched local development WebGL player: start the worker with `--web-root <development-build-directory>` and open its local game page. The page's Start button sends `StartWatchedSuite` to `[LOCAL JEV LAUNCHER]`. This isolates test saves under `persistentDataPath/CSR-jev-test`, captures the game's real portrait camera, and returns the final report to `/api/suite-result`. Public release builds do not contain this launcher or bridge.
4. A fresh Editor process can also run the harness without `-quit`, but its **actual Game View must be portrait**. Editor screen flags alone do not guarantee that:

   ```text
   Unity.exe -batchmode -projectPath <repo> -executeMethod ColorStackRush.Testing.JevSuiteEditorRunner.Run -jevEndpoint http://127.0.0.1:8877 -jevReport <absolute-test-artifact-directory>/unity-summary.json -screen-width 540 -screen-height 960 -logFile <absolute-log-file>
   ```

The Editor entrypoint temporarily enables `CSR_JEV_TEST`, waits through recompilation, enters an unsaved test scene and uses isolated temporary save storage. It restores the original define settings and normal save path after stopping Play Mode. On an interrupted run, execute `ColorStackRush.Testing.JevSuiteEditorRunner.StripTestDefine` before any release build. Test bridge runtime code is guarded by **`CSR_JEV_TEST && (UNITY_EDITOR || DEVELOPMENT_BUILD)`** and is absent from the public WebGL player. The release builder must also strip the opt-in symbol.

Both players record `viewportWidth`, `viewportHeight` and `cameraAspect`, and reject landscape or mismatched camera/screen ratios. The default watched page uses a 540×960 backing buffer. Other real pointer devices are temporarily suppressed during play so a viewer cannot steer the AI run; they are restored on pause to allow the ordinary Resume button and restored completely after testing. A paused run makes no new AI calls, excludes paused duration from its timeout/report, and rejects any pending response as stale. The normal product pause behavior remains enabled.

The suite plays levels **1, 4, 6, 7, 12, 13, 19 and 1,000**, with profiles `normal`, `extra_150ms`, `extra_300ms`, and `one_bad_then_recover`. The final profile logs an explicit test override of one accepted model action; the model then continues deciding. Unity applies all movement with 200 ms synthetic mouse gestures through the normal `SwipeInput`/`FixedUpdate` pipeline, never by setting the player position. Gate timing, speed, health and collision rules are the shipped ones.

The recovery override is selected only when the current observed lane is safe and a bounded drag moves toward a visible wall footprint. Action logs retain both the actual model choice and the override's predicted position/wall bounds. The run report separately records command acceptance, measured movement and contact with the target wall; a run without an applied perturbation cannot be reported as a completed recovery trial.

The model is not given the seed, `CoursePlan`, route points, safe-X, movement phases, unopened color warnings or objects outside the frustum/behind occluders/covered by opaque UI overlays. The worker rejects unexpected observation fields. Relative left/right descriptions and currently visible opening bounds are derived only from the observed geometry, not a planner or action-selection policy; all action choices still come from Jev. Model-facing numbers are rounded to two decimals to avoid unnecessary floating-point noise. Wrapper suite/run/profile/viewport identifiers are used for logging and artificial latency only and are not sent to Jev.

Output files are `decisions.jsonl` (actual observation, rounded model state, answers/token counts/latency), `actions.jsonl` (accepted or rejected actions and reasons), `runs.jsonl`, `driver-summary.json`, `suites.jsonl`, and `unity-summary.json` received directly from Unity. `GET /api/status` returns only model/current level+profile/finished-run count/completion/normal wins/last accepted action for the watch page. Exit status is **0** when at least 6/8 normal runs succeed including levels 1 and 4, **2** for transport/harness failures, or **3** when the gameplay/model target is missed. Runs with no fresh answer are classified as connection-latency failures. A failed target is reported, not relabeled as passing. Inspect actual traces and compare the intended-route physics bot before assigning blame to model decisions or parkur difficulty.

Documentation verified October 2026: [models](https://docs.typesafe.ai/models), [HTTP API](https://docs.typesafe.ai/api), [Choice](https://docs.typesafe.ai/primitives/choice).
